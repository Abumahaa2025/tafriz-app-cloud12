# رفع نسخة APK جديدة بأمان

الملف المنشور للمستخدمين هو `public/downloads/Tafriz.apk`، وينزّلونه من
`https://tafriz-app-cloud12.vercel.app/install.html`.

التطبيق **ليس** نسخة Capacitor — هو غلاف **TWA** (Trusted Web Activity) اسم حزمته
`com.tafriz.app`، وكل شاشاته تُحمَّل من الموقع نفسه. يعني: تحديثات الواجهة والفرز
والتشيك تصل للمستخدم من نشرة Vercel مباشرة، وما يحتاج APK جديد إلا لو تغيّر شيء
داخل الغلاف نفسه (الأيقونة، اسم الحزمة، الأذونات، رابط الموقع).

## ليش النسخة السابقة كانت تعطي «لم يتم تثبيت التطبيق»

الحزمة اللي كانت منشورة اتفكّت وأُعيد ضغطها بأداة zip عامة ثم وُقّعت بـ `jarsigner`.
هذا كسر ثلاثة شروط إلزامية في أندرويد 11 فأحدث دفعة واحدة:

| الشرط | حالة النسخة المكسورة | النتيجة على الجوال |
| --- | --- | --- |
| توقيع APK Signature Scheme v2 فأعلى (إلزامي لـ `targetSdk` 30+) | توقيع v1 فقط | يُرفض التثبيت فورًا |
| `resources.arsc` مخزّن بدون ضغط ومحاذى 4 بايت (إلزامي لـ `targetSdk` 30+) | مضغوط | يُرفض التثبيت فورًا |
| أسماء الملفات داخل الحزمة تستخدم `/` | 443 ملفًا بـ `\` | لا يجد `res/` فتضيع الأيقونة والواجهات |

`targetSdk` في هذه الحزمة هو 35، فكل الشروط الثلاثة تنطبق عليها.

## الفحص قبل أي رفع

```bash
npm run verify:apk
```

يفشل الأمر ويمنع الرفع إذا رجع أي شرط من الثلاثة للخطأ. شغّله دائمًا بعد أي تعديل
على `public/downloads/Tafriz.apk`.

## بناء وتوقيع حزمة جديدة

لا تفك ضغط الـ APK وتعيد ضغطه أبدًا. ابنِ من المصدر ثم وقّع بـ `apksigner` (وليس
`jarsigner`، لأن `jarsigner` يعرف توقيع v1 فقط):

```bash
# 1) محاذاة (لازم قبل التوقيع، لا بعده)
zipalign -p -f 4 app-release-unsigned.apk app-aligned.apk

# 2) توقيع بكل المخططات
apksigner sign \
  --ks tafriz-release.keystore --ks-key-alias tafriz \
  --min-sdk-version 23 \
  --v1-signing-enabled true --v2-signing-enabled true --v3-signing-enabled true \
  --out public/downloads/Tafriz.apk app-aligned.apk

# 3) تأكيد
apksigner verify --verbose --print-certs public/downloads/Tafriz.apk
npm run verify:apk
```

`apksigner` و `zipalign` يجيان مع Android SDK Build Tools.

## مفتاح التوقيع

النسخة الحالية موقّعة بمفتاح جديد، بصمته SHA-256:

```
92:79:6C:5C:12:B4:5B:37:83:A9:13:CF:87:52:9F:84:0C:EE:AD:E8:2C:CA:34:E8:C0:0A:B9:40:A7:F2:53:32
```

هذه البصمة مضافة في `public/.well-known/assetlinks.json` مع البصمات القديمة — لا
تحذف القديمة حتى لا تنكسر أي نسخة مثبّتة سابقًا.

قواعد ثابتة:

- **لا ترفع ملف الـ keystore للمستودع** — المستودع عام، وأي أحد يحصل عليه يقدر
  يوقّع تحديثًا خبيثًا يُثبَّت فوق تطبيقك. خزّنه في GitHub Secrets.
- أي حزمة جديدة لازم تُوقَّع **بنفس المفتاح**، وإلا ما تقدر تُثبَّت كتحديث فوق
  المثبّتة ولازم المستخدم يحذف القديمة أولًا.
- ارفع `versionCode` مع كل نسخة (الحالية `2`)، وإلا أندرويد يرفض تثبيتها كتحديث.

## ملاحظة مفتوحة

الحزمة الحالية ما فيها إذن `android.permission.INTERNET`. مسار TWA الأساسي يشتغل
بدونه لأن التحميل يتم داخل Chrome، لكن مسار `WebViewFallbackActivity` (الجوالات
اللي ما فيها متصفح يدعم TWA) يحتاجه. إضافته تتطلب إعادة بناء الغلاف من المصدر
بـ Bubblewrap؛ لا تُضاف بتعديل الحزمة الجاهزة.
